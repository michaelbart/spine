# Audit — 2026-08-22

An independent, adversarial audit of spine (skills, hooks, scripts, agents,
templates, docs), run against the state of `main` after commit `716087d`
("fix: floor gate bugs found in audit; clean up dangling doc references").
Four parallel reviewers each covered one subsystem; every finding below was
verified against actual code execution or direct tracing, not comments.
Confirmed fixes are applied on `main` as of this document; each entry says
what was done.

## Hooks — `core/hooks/*`

**A single `../` in a file path bypassed all three enforcement hooks
(phase-gate, path-escalate, dep-gate).** `core/hooks/_workspace-route`
built `abs_path` by plain string concatenation with no `.`/`..`
normalization, so every glob match downstream (protected-paths.conf,
task-folder confinement, manifest patterns) compared against a literal,
unresolved path string. `path-escalate` with `src/auth/**` protected: a
direct write to `src/auth/secret.txt` was denied; the identical file
reached via `src/other/../auth/secret.txt` was allowed. Same root cause
independently affected `phase-gate`'s task-folder containment check
(which recomputed its own `abs_path` rather than using the shared
helper's) and `dep-gate`'s manifest match.
**Fixed:** added `_wsr_collapse()` (a lexical, filesystem-independent
path normalizer, 3.2-compatible — no negative array indices, which are a
bash 4.2+ feature this codebase already elsewhere guards against on
macOS's system bash) to `core/hooks/_workspace-route`, applied to
`workspace_route`'s own `abs_path` and to `phase-gate`'s independent
recomputation. Verified with direct traversal repros (single-repo and
workspace-mode fixtures) before and after.

**Hooks could plausibly fail open on their own internal breakage.**
Under `set -uo pipefail` (no `-e`), a missing/broken sourced helper
(`_workspace-route`, `_bash-write-targets`) failed non-fatally at
`source` and only died later via `set -u` on an unbound variable — exit
code 1, not the `exit 2` every comment calls "fail closed." Whether
Claude Code's hook runner treats exit 1 the same as exit 2 wasn't
independently verifiable.
**Fixed:** added an explicit `declare -F <function> || exit 2` check
immediately after every `source` in `phase-gate`, `path-escalate`, and
`dep-gate`, with a clear message. Verified: a hook with its
`_workspace-route` sibling deliberately removed now exits 2 with
"failing closed, cannot evaluate this write safely," not a bare unbound-
variable crash.

## Scripts — `core/scripts/*`

**The Class 2 smoke hard-gate fix (716087d) broke `core-selftest`.**
`core-selftest`'s `new_migrate_fixture()` set `smoke-seed/run/golden` to
`"not-applicable"`; the now-correct Class 2 gate (hard-fails unless
`smoke-run` is `"implemented"`) started failing three unrelated
migrate-rehearse assertions for a reason the test wasn't checking,
masking its own real coverage. The regression suite meant to guard this
exact code path didn't itself get run before the fix that touched it
shipped.
**Fixed:** `new_migrate_fixture` now gives itself a trivial passing
smoke-seed/run/golden stub. `core-selftest` is green again (verified).

**A dangling `g1-tee-waitlist testbed finding` citation, missed by
716087d's own cleanup pass, in four places:** `core/scripts/floor:34-36`
(a near-duplicate of a comment 70 lines later that *was* cleaned up in
the same commit — this earlier copy wasn't), `core/skills/bootstrap/
SKILL.md:227` (`phase-A-handoff.md §2.1`), `core/skills/task/
SKILL.md:346` (`ext-c-phase-A-handoff.md §0.2`), and `core/ADAPTER-
CONTRACT.md:553-554` (a second copy of the same citation the commit fixed
once elsewhere in the same file, at what's now line 267). All four cited
a document that no longer exists anywhere in the repo (deleted when spine
was uninstalled from itself).
**Fixed:** all four reworded to state the underlying fact directly,
without the dead citation — the same pattern 716087d itself used for the
instances it did catch. Repo-wide grep now finds zero remaining
references to `g1-tee-waitlist` (note: it was line-wrapped as `g1-tee-`
/ `waitlist`, which is why a naive single-line grep missed some of these
the first time).

**Ledger fields written every task, several never read by anything.**
`conformance_score`, `second_approver`, and four `ship_time_regrounding_*`
fields were written by `/verify`/`/ship` — two of them (`ship_time_
regrounding_floor`/`_index`) with skill-instruction text explicitly (and
incorrectly) claiming `/costs` reads them — but neither `ledger
aggregate` nor `render-task` (the `/task-report` generator) consumed any
of the six. A separate, genuinely dead field, the unsuffixed
`ship_time_regrounding` (distinct from the four real suffixed fields),
was seeded at `ledger init` and never set or read by anything at all.
**Fixed:**
- Removed the dead unsuffixed `ship_time_regrounding` field from `ledger
  init`'s schema.
- Added `conformance_score` and `second_approver` to `ledger aggregate`
  (both the plain and `--by-engineer` views) as `avg_conformance_score`
  and `second_approver_count` — these are genuinely numeric/countable, a
  clean fit for a cross-task rollup. `core/skills/costs/SKILL.md` updated
  to report them.
- Added a new "Conformance, approval & re-grounding" section to
  `render-task` surfacing all six fields (plus two new ones, see below)
  per-task — the four free-text `ship_time_regrounding_*` fields are
  diagnostic strings better read per-task than force-aggregated, so they
  live here rather than in `ledger aggregate`.
- Corrected `ship/SKILL.md`'s two false claims that `_floor`/`_index`
  feed `/costs` — they're recorded for `/task-report` instead, which is
  now literally true.
- Verified end-to-end: a synthetic ledger.json with all fields set
  renders correctly in both `ledger aggregate` and `render-task`'s new
  section.

**The 200-line plan cap and ≤1-page briefing cap had zero mechanical
backstop** — pure self-reported instructions with no script ever
recording or checking the actual line count, so an oversized artifact
under pressure would never surface anywhere.
**Fixed:** `task/SKILL.md` and `ship/SKILL.md` now record the actual
`wc -l` count (`ledger set <task-id> plan_line_count <n>` /
`briefing_line_count <n>`) — ship/SKILL.md's "≤1 page" is now
operationalized as ≤60 lines, matching `CLAUDE.md`'s own cap convention.
`render-task` flags an over-cap count explicitly. This is still not a
hard gate (consistent with this system's own stated posture — "one layer
is a real hook, everything else is a script an agent is instructed to
act on"), but it closes the visibility gap: an oversized artifact is now
a recorded, checkable fact instead of invisible unless someone happens to
notice.

**Class 2 is now permanently unreachable for a project with no
smoke-testable runtime**, an undisclosed consequence of the (correct)
smoke hard-gate fix — unlike every other capability, smoke has no
legitimate `not-applicable` escape hatch.
**Fixed:** disclosed in `docs/tradeoffs.md`'s "Known limits" — this
appears to be deliberate (no Class-2-risk work ships without a working
smoke harness), not a bug, but wasn't previously stated anywhere.

## Skills & docs

**README.md contradicted `task/SKILL.md` and `docs/tradeoffs.md` on plan
approval.** "This is the one stop that always happens" (README) vs. "If
`autonomy` is `auto`, there is no plan-approval stop" (`task/SKILL.md`)
vs. tradeoffs.md's own disclosure that `auto` "skips plan approval
entirely" — and the `standard` profile preset sets `autonomy_ceiling:
auto` by default, so this isn't a rare edge case.
**Fixed:** README's six-step walkthrough now names the `auto`-mode
exception in one clause.

**README's Layout table mischaracterized `core/agents/`** — omitted
`surveyor.md` (a real, first-class `/adopt` agent) and called the set
"read-only" when `falsifier.md` explicitly requires `Edit`/`Write` in an
isolated worktree for its stub-out mutation-testing mandate — the
README's own "Why" section states this two lines above the table that
contradicts it.
**Fixed:** table now lists all four agents, drops the false "read-only"
claim.

**`/workspace`'s §6 heading ("Verify the fallback, *once*, before calling
this done") contradicted §0's own explicit text** ("§6 [is] unchanged by
[extend mode]... [it cares] about repos and contracts, not about whether
this is the workspace's first or fifth repo" — i.e., it's designed to run
on every extend, not once). The literal mechanism §6 checks (hooks
degenerate correctly when `workspace.json` is absent) is proven by
construction and doesn't need re-checking; what's actually being verified
each time is whether *this newly-added repo's own* hook wiring installed
correctly — a real, non-redundant, per-repo check, just mislabeled by
the heading's "once."
**Fixed:** reworded the heading and opening sentence to state the
per-repo framing directly, matching §0's own description rather than
contradicting it.

**Near-verbatim duplicated prose between `falsifier.md` and
`security.md`** (~20-line "Reporting discipline" / "Verify each piece of
evidence once" / "Be efficient" blocks) had already drifted slightly in
wording beyond the intentional domain-word swaps ("scenario" vs.
"attack"). No shared-include mechanism exists for agent-file bodies.
**Fixed:** added a one-line HTML comment above each block in both files
pointing at its twin, so a future edit to one is a visible prompt to
check the other.

## Not changed — judgment calls, not bugs

- **Adversary findings still don't gate `/ship`.** Confirmed as designed,
  matches `docs/tradeoffs.md`'s existing disclosure exactly. No change.
- **The line-cap fix is visibility, not enforcement.** A determined or
  rushed session can still ship an over-cap plan/briefing; the ledger
  field just makes it visible after the fact rather than invisible. A
  genuine hard gate (failing `/verify` or `/ship` outright) was
  considered and rejected as scope creep beyond what this audit's
  findings actually called for — the audit's own suggested fix was
  explicitly "a loud, non-blocking note."

## Process note for next time

The commit that prompted this audit (716087d) fixed two real bugs in
`core/scripts/floor` but didn't run `core/scripts/core-selftest` first —
which would have caught the regression it introduced in the same commit.
Any change to `floor`'s gating logic should run `core-selftest` before
and after, every time, not just when a fixture happens to catch it.
