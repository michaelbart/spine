## 4. Decisions made and reasoning

**Adapter argument convention (open question §5.7), decided in `core/ADAPTER-CONTRACT.md`:** changed-file sets travel on stdin (newline-separated, relative paths); an output artifact path is always the first positional argument; a base ref for diffing is `SPINE_BASE_REF` (env var, default `HEAD`), never positional. Chosen over alternatives (e.g. `--flag value` pairs) because it's the smallest convention that covers all 13 capabilities without any capability needing more than one positional argument, and because stdin for potentially-large changed-file sets avoids `ARG_MAX` risk that a long argv could hit on a big changeset.

**The `--self-test pass|fail` protocol** is the one mechanism decision in this phase that isn't directly specified by the build prompt (which says adapter-conformance "feeds each adapter a known-passing case and a known-failing case" but not how the fixture reaches the adapter). Decided: every adapter builds its own fixture, in its own temp scratch space, for both modes — this keeps `adapter-conformance` itself 100% stack-blind (it only ever invokes `--self-test pass`/`--self-test fail` and checks exit code + line count) and gives a hand-written adapter author the exact same validation path the installer uses. The alternative (a separate stack-specific fixture directory adapter-conformance reads) would have leaked stack knowledge into the conformance suite itself, which the build prompt explicitly forbids ("No file in the spine ... may reference a language, framework, or tool"). Recorded per build prompt §1's "your judgment may win on a mechanism's details" allowance.

**Task-ID and commit-trailer convention (open question §5.1), decided:** `<YYYYMMDD>-<kebab-slug>` task IDs, `Spine-Task: <id>` commit trailer, `Spine-Bypass: <reason>` for `--bypass`. Confirmed against horizon's real commit history: existing commits already carry a `Co-Authored-By:` trailer with no conflict, and horizon's CI enforces Conventional-Commits-style PR titles via `semantic_pull_request.yml` — a trailer composes cleanly with a `feat:`/`fix:` subject prefix without fighting either convention. This directly unblocks `ledger scan-untracked-ratio`, which is mechanical grep, no model judgment.

**`typecheck`/`lint` split for this stack**, refining Phase A's already-confirmed Layer 3 answer: `flutter analyze` conflates true type errors with `very_good_analysis` style/lint findings in one output stream (there is no `--errors-only` flag; `--no-fatal-infos`/`--no-fatal-warnings` control which severities are *fatal to the process exit code*, not which are *printed*, and empirically didn't change `flutter analyze`'s own exit code at all on this version). `typecheck` therefore greps the output for `error`-severity lines specifically (matching either `flutter analyze`'s `•`-separated format or bare `dart analyze`'s `-`-separated format, since the adapter's self-test uses the lighter bare `dart analyze` and the real invocation uses `flutter analyze`) and ignores info/warning lines. This means horizon's 5,913 pre-existing lint-level findings never block `typecheck` — they were never going to be `lint`'s job either under Phase A's split (`lint` = `dart format` + eslint only), so as built, style-level `very_good_analysis` findings ride along in `typecheck`'s output but block nothing. **This is a real, disclosed gap in coverage, not a hidden one**: nothing in the current 13-capability floor actually gates on Dart lint-rule violations, only on formatting. Worth a `/ratchet` candidate once this is felt in practice, per build prompt §2.6 — not something to silently patch in now.

**`mutate` and the four `smoke-*`/`migrate-rehearse` capabilities are `unavailable`**, not implemented, not `not-applicable`:
- `mutate`: confirmed (Phase A's research, re-checked here) no mature Dart/Flutter mutation-testing tool exists on pub.dev. The falsifier's stub-out probe is the explicit fallback per build prompt §2.5.
- `smoke-*`/`migrate-rehearse`: horizon has **no local Firebase emulator configuration** — `firebase.json` has no `emulators` block. The existing `bin/debug demo` flavor, which looked like it might be reusable smoke infrastructure, actually seeds fixed personas against a **real cloud Firestore project** (`turnpilot-dev`), confirmed by reading the commit history and `lib/demo/demo_seed.dart`'s surrounding code — not a local emulator at all. Building genuine local emulator infrastructure (an `emulators` block, a seed script, safe isolation from the real `turnpilot-dev`/`horizon-cafc1` projects) is real, substantial, legitimate scope — but it's new infrastructure the repo doesn't have today, not an adapter wrapping existing tooling, and doing it improvised under Phase B's time budget risked either a half-safe emulator setup or (far worse) a mistake that touches a real cloud project. Marked `unavailable` with the reason spelled out rather than attempted unsafely. **This is the most consequential open item for Phase D or a dedicated follow-up task** — `migrate-rehearse` in particular is supposed to be *the* mechanical backstop for `firestore.rules`/`firestore.indexes.json` changes, and right now nothing plays that role for horizon.
